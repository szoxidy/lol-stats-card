# 远程数据来源核验

核验日期：2026-11-13。目标为国服账号只配置昵称、标签与大区，不要求玩家登录或启动游戏客户端。当前没有通过实测的远程来源，服务继续返回`automatic=false`。

## 已核验的边界

| 来源 | 已见证据 | 当前结论 |
| --- | --- | --- |
| [LeagueAkari令牌维护源码](https://github.com/LeagueAkari/LeagueAkari/blob/main/src/main/shards/sgp/token-state-controller.ts) | 跟随`leagueClient.data`中的entitlements及league-session令牌 | 能查其他ID仍需要已认证会话，不是匿名服务端API；没有独立登录或长期续期的实现证明 |
| [Ezhana/lcu](https://github.com/Ezhana/lcu/blob/main/sgp.go) | SGP使用Bearer认证；`RefreshToken`由作者标注“疑似过时” | 仅有旧续期函数不能证明客户端退出后还能长期查询；没有进行真实令牌迁移或续期测试 |
| [应天API个人资料接口](https://api.t1qq.com/doc/56) | 文档要求接口密钥与掌盟号ID，更新日期2024-03-11；未提供实际战绩结构 | 候选尚未验明覆盖国服账号、模式历史、刷新规则及实际返回；没有配置或调用密钥，不能先编造适配器 |
| [lol-tracker公开API](https://lol-tracker.cn.lt/API.md) | 匿名读取已收录缓存；resolve不登记账号、不查询上游；平台枚举不含大陆国服 | 不能用它按任意国服ID建立持续更新；未请求其他玩家资料 |

没有尝试伪造登录状态、复用公开示例令牌、调用未公开的登录绕过流程，或将本机凭据上传到服务器。玩家已明确不接受首次扫码或其他登录，因此不将无界面登录当作替代方案。

## 接入前的实际验收

先拿到覆盖目标大区的真实返回，确认账号关联、段位、队列筛选与来源时间，再测试客户端未启动时重复查询及新对局出现。来源的响应生成时间不能冒充战绩更新时间。需要服务商密钥、费用或额外账号授权时，必须先明确条件；没有可调用来源时不启动空跑调度。

## 主页如何更新

主页一次性引用展示服务的固定`/card.svg?queue=...`。后台取数后发布白名单快照，两个地区分别保存数据；图片请求只读取该端数据，不触发跨境回源或上游查询。同一URL在数据变化后返回新内容和新ETag，客户端缓存按响应头重新验证。更新数据不需要构建或上传主页`dist`。

目前只有快照写入与动态图片读取的闭环通过测试，上游自动取数和两地生产部署仍未完成。
